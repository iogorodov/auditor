# Аудитор — гайд для работы над проектом

PWA для аудита электроснабжения на объектах. Аудитор составляет список замечаний, выбирая их
из предопределённого каталога (плюс свои). Полностью offline, без бэкенда.

## Карта версий

Документация разбита по версиям — каждая следующая опирается на предыдущую.

| Версия | Файл | Scope |
|--------|------|-------|
| 0 | `docs/VERSION_0.md` | Базовый сетап: скелет проекта, `index.html` + `app.ts` + `app.css`, hello-world тест, `bun start` (localhost:8008, hot reload). **Обоснование стека.** |
| 1 | `docs/VERSION_1.md` | Основная логика приложения без PWA. Проверка — только через `http://localhost`. **§9 — обоснования логики.** |
| 2 | `docs/VERSION_2.md` | Экспорт аудита и пользовательских замечаний в `.xlsx`; обновление каталога из `.xlsx`-файла (вместо Google-таблицы). Собственный xlsx-код в `src/xlsx`. |
| 3 | `docs/VERSION_3.md` | Два этапа: **3а** — прод-сборка + CI + деплой на GitHub Pages (online); **3б** — PWA (manifest + Service Worker, офлайн). |

Эталон вёрстки — `docs/layout-mockup.html` (описан в `VERSION_1.md`). Обоснования решений
(«почему так») лежат в самих версиях (V0 — стек, V1 — §9).

**Версии — источник истины.** При новых решениях обновляй соответствующий VERSION-файл: он приоритетнее
кода и памяти. **Текущий фокус: Версии 1–3 завершены (3а online-деплой + 3б PWA). Приложение в проде,
устанавливается и работает офлайн.**

## Правила работы с версией

Каждая версия делается одним промптом на чистом контексте. Порядок:

1. **Прочитай документацию по версии** (соответствующий `docs/VERSION_N.md`, при необходимости — смежные).
2. **Уточни все необходимые вопросы** до начала реализации (в т.ч. пункты «Прежде чем приступать»).
3. **Декомпозируй версию на целостные задачи:**
   - каждая задача что-то **добавляет** в приложение (снятие риска — тоже добавление);
   - после каждой задачи приложение **остаётся рабочим**;
   - все задачи про **снятие рисков** выноси как можно раньше.
4. **Выполняй задачи по порядку.** После каждой задачи:
   - прогоняй тесты;
   - как задача завершена — **коммит с коротким (в одну строку) сообщением**;
   - переходи к следующей.

**Пуш делает только пользователь.** Агенты коммитят локально, но `git push` не выполняют
(push в `master` запускает CI и деплой на Pages — это ручное действие пользователя).

## Стек и команды

- **Bun + TypeScript + CSS.** Без фреймворка; из внешних пакетов — Sortable.js (drag) и fflate
  (zip для `.xlsx`, V2).
- `bun start` — дев-сервер с hot reload на `http://localhost:8008`.
- `bun test` — юнит-тесты.
- Разработка и проверка — **только через `http://localhost`** (не `file://`). PWA-сборка — в V3.

## Архитектурные инварианты

- **Ядро отдельно от DOM:** доменная логика в `src/core/*.ts` без обращений к браузеру; UI импортирует её.
  Ядро покрывается `bun test` без браузера.
- **Сборка (V3):** `bun run build` = `scripts/build.ts`. Два выхода — `chunk-[hash].js/css` (из
  `index.html`) и отдельный `sw.js` (без хэша, стабильное имя, со списком пред-кэша из реального `dist`).
  Статика (`manifest.webmanifest`, иконки) — из `public/` мимо бандлера, стабильные имена.
- **Безопасный рендер:** строки пользователя/CSV — только через `textContent`/DOM-узлы, не `innerHTML`.

## Ключевые доменные правила (кратко; детали — в VERSION_1.md)

- **Иерархия** — шаблон из Google-таблицы, ровно 2 уровня; на каждом уровне **ровно один изменяемый слот**.
- **Каталог замечаний** — из таблицы; замечание = `текст` + `категория` + `область`(привязка). Привязка
  сопоставляется по **шаблонным именам слотов** (листа или родителя-уровня-1), без регистра/пробелов.
- **Аудит — снимок** (вложенное дерево имён + тексты замечаний). Связь с каталогом по совпадению текста; без ID.
- **Обновление каталога — бинарное:** есть ошибка → не применяем. Ровно две ошибки (структура иерархии;
  привязка на несуществующий узел).
- **Нормализация строк:** space-like → пробел, схлопывание двойных, обрезка краёв — и для CSV, и для ввода.
