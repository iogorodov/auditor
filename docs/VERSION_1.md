# Версия 1 — основная логика приложения (без PWA и экспорта)

Полная предметная логика и интерфейс. Работает и проверяется **только через `http://localhost`**
(`bun start`, см. [`VERSION_0.md`](./VERSION_0.md)). Обоснования решений — в конце файла (§9).
Визуальный эталон вёрстки — [`layout-mockup.html`](./layout-mockup.html).

**Что отложено:** экспорт `.docx`/`.xlsx` → [`VERSION_2.md`](./VERSION_2.md);
PWA (manifest + Service Worker), прод-сборка, CI и деплой → [`VERSION_3.md`](./VERSION_3.md).

## Прежде чем приступать

- **Проверить CORS** реального published-CSV из браузера. Экспорт отдаёт 307-редирект на
  `googleusercontent.com`; нужно убедиться, что браузерный `fetch` проходит cross-origin на **реальной**
  таблице (curl с сервера это не проверяет). Если не проходит — рассмотреть gviz-endpoint
  `/gviz/tq?tqx=out:csv&gid=<GID>` или прокси.
- Данные каталога — **получены** (§4), формат учтён (в реальном каталоге колонки `Категория, Текст, Область`,
  «Категория» — группами сверху вниз).

## 1. Назначение

Приложение для **аудита электроснабжения** на объектах (эксплуатируемые или строящиеся здания).
Задача — упростить составление списка замечаний под конкретный аудит.

Ключевая идея: вне зависимости от типа объекта (театр, гараж, цирк) проблемы электроснабжения
похожи. Поэтому в приложении есть **предопределённый каталог замечаний**, сгруппированный по
категориям, из которого аудитор быстро отмечает нужное, а не печатает каждое замечание с нуля.
Плюс можно добавлять свои замечания.

## 2. Рамки и технические принципы версии

- **Портретный мобильный экран** — работа на объекте с телефона (веб-страница в браузере).
- **Полностью offline:** данные — в браузере (**IndexedDB**), своего бэкенда нет.
- **Разработка и проверка — на `http://localhost`** (`bun start`). Service Worker, manifest и прод-сборка
  в этой версии **не делаются** (V3); всё, включая «Обновить каталог» и IndexedDB, отлаживается на localhost.
- **Ядро отдельно от DOM:** вся доменная логика — в `src/core/*.ts` без обращений к браузеру; UI импортирует её.
- **Первый запуск требует интернета** — до первой команды «Обновить каталог» каталог пуст; зашитого дефолта нет.

## 3. Модель данных

Четыре категории данных:

| # | Данные | Источник | Хранение | Выгрузка |
|---|--------|----------|----------|----------|
| 1 | **Иерархия** (шаблон уровней 1–2) | Google-таблица | offline-кэш | — |
| 2 | **Каталог замечаний** (предопределённые) | Google-таблица | offline-кэш | — |
| 3 | **Аудиты** | создаются в приложении | только offline | — (экспорт → V2) |
| 4 | **Пользовательские замечания** | создаются в приложении | только offline, редактируемы | — (экспорт → V2) |

Пользовательские данные (3, 4) наружу не выгружаются. Эталонные (1, 2) в приложении **не редактируются** —
только через таблицу и команду «Обновить каталог».

### 3.1. Иерархия (шаблон)

Шаблон, применяемый **внутри каждого «Здания» аудита**. Всегда **ровно два уровня**.

- **Уровень 1** — упорядоченный список слотов; у каждого `имя` + `тип`.
- **Уровень 2** — у каждого слота уровня 1 свой упорядоченный список слотов; у каждого `имя` + `тип`.
- `тип` слота:
  - **фиксированный** — ровно один узел с этим именем, всегда присутствует;
  - **изменяемый** — пользователь добавляет/удаляет экземпляры этого типа; у экземпляров свои названия.
- **На каждом уровне (в пределах одного родителя) — ровно один изменяемый слот**, остальные фиксированные.
  Строго один: неразрешённые имена из снимка аудита падают именно в него (см. §3.4). Следствие: кнопка
  «Добавить» однозначна — добавляет экземпляр единственного изменяемого типа этого уровня.
- Узлы **уровня 1 — контейнеры**: замечаний не содержат, только агрегируют счётчик детей. Замечания живут
  только в **листьях уровня 2**.

Пример:

```
Уровень 1 (изменяемый: «Помещение»)
├─ Документация      (фиксированный)
│  ├─ Здание          (фиксированный лист)
│  └─ Другое          (изменяемый лист)
├─ Общее             (фиксированный)
│  └─ Другое          (изменяемый лист)
└─ Помещение         (изменяемый) ── экземпляры со своими названиями
   ├─ Помещение       (фиксированный лист)
   └─ Щит / панель    (изменяемый лист)
```

### 3.2. Каталог замечаний (предопределённые)

Каждое замечание: `текст` (одна логическая строка), `категория` (строка), `привязка` (список имён-слотов).

**Правило привязки.** Замечание применимо к листу уровня 2, если его список привязки содержит имя,
совпадающее с именем **самого листа** *или* его **родителя (уровень 1)**.
- Имена здесь — **шаблонные имена слотов** иерархии (напр. «Помещение», «Щит / панель»), **не**
  пользовательские названия экземпляров. Пример из реальных данных: привязка «Помещение» попадает и в
  фиксированный лист «Помещение», и во все листья «Щит / панель» (их родитель — слот «Помещение»).
- Разделитель — точка с запятой `;`.
- Сравнение имён — без учёта регистра, с обрезкой пробелов по краям (после нормализации, §4).
- Имя элемента иерархии со знаком `;` сослаться нельзя.
- **Пустая привязка = применимо везде.**

Примеры: `Документация` → во всех листьях под «Документация» («Здание», «Другое»); `Щит / панель` → во всех
щитах; `Помещение; Щит / панель` → в фиксированном листе «Помещение» и во всех щитах.

**Категории** заданы в листе «Замечания» колонкой «Категория» с заполнением сверху вниз (пустая ячейка = та же
категория, что строкой выше — как уровни в листе «Иерархия»). Список категорий = различные заполненные значения;
отдельного справочника нет (опечатка → две похожие категории). Сортировка категорий по имени, **«Прочее» всегда
внизу**. Порядок замечаний внутри категории = порядок строк.

### 3.3. Пользовательские замечания (глобальный список)

- Глобальный, **переиспользуемый** список; **редактируется** в приложении (экран «Мои замечания», §6.7).
- Поля те же: `текст`, `категория`, `привязка`. При добавлении пользователь указывает привязку
  (по умолчанию — все) и категорию (выбор из существующих или ввод новой).
- В списке выбора замечаний пользовательские идут после предопределённых, **по алфавиту**, и ничем визуально
  не выделяются.

### 3.4. Аудит (снимок)

Аудит хранит **снимок**: вложенное дерево узлов (по именам) с выбранными текстами замечаний. Стабильные ID
не используются — связь с каталогом только по совпадению строк (без учёта регистра, обрезка пробелов).

Структура: `Аудит → buildings[] → nodes[] (уровень 1) → nodes[] (уровень 2) → remarks[]`. Узлы хранятся
**явно, включая фиксированные**. Порядок в массивах = ручной порядок пользователя.

```json
{
  "name": "Audit #1",
  "time": 1785175271,
  "buildings": [
    {
      "name": "Гараж",
      "nodes": [
        {
          "name": "Документация",
          "nodes": [
            { "name": "Здание", "remarks": ["Все пропало"] },
            { "name": "Схемы",  "remarks": [] }
          ]
        },
        {
          "name": "Основное строение",
          "nodes": [
            { "name": "Помещение",     "remarks": [] },
            { "name": "Щит ЧЗНХ №12", "remarks": ["Нет заземления"] }
          ]
        }
      ]
    }
  ]
}
```

- `name` аудита обязателен; `time` — unix-время последнего изменения (дата в списке считается из него).
- `remarks` — множество выбранных **текстов**; ручной порядок внутри листа не хранится (выводится:
  предопределённые — по каталогу, пользовательские — по алфавиту).

**Разрешение имён и слияние снимка с текущей иерархией при отображении:**
- Порядок и подписи **фиксированных** узлов — из шаблона; порядок **изменяемых** экземпляров — из массива
  `nodes`; позиция изменяемой группы среди фиксированных — из шаблона.
- Каждое имя разрешается против шаблона: совпало с фиксированным слотом уровня → этот фиксированный узел;
  иначе → экземпляр **единственного изменяемого** слота, сохранённое имя = его название.
- Пропал фиксированный слот из каталога → узлы с этим именем становятся изменяемыми экземплярами.
- Фиксированные слоты шаблона, которых нет в снимке, **подмешиваются пустыми**.
- Поведение обратимое: правки иерархии перекладывают замечания между узлами, откат правок возвращает как было.

**Категория замечания в аудите** не хранится, а разрешается: текст совпал с записью каталога или
пользовательского списка → берётся её категория; не нашёлся нигде → показывается в **«Прочее» как
пользовательское**. «Отмечено» в листе = текст замечания из каталога совпал с текстом сохранённого элемента.

## 4. Источник данных: Google-таблица

> **Заменено в Версии 2:** каталог обновляется из локального `.xlsx`-файла с теми же листами
> (см. `VERSION_2.md`); CSV-ссылки и сетевой путь из приложения убраны. Форматы листов и правила §5 действуют.

Одна публичная (read-only) таблица, два листа. В приложении **зашиты две ссылки на CSV**, команда «Обновить
каталог» тянет оба.

Таблица (ID): `<SPREADSHEET_ID>` (ID реальной таблицы в публичный репозиторий не включается).
CSV-экспорт листа: `https://docs.google.com/spreadsheets/d/<ID>/export?format=csv&gid=<GID>`
- **Иерархия** — `gid=<GID_HIERARCHY>`
- **Замечания (каталог)** — `gid=0`

**Нормализация строк** (при чтении из CSV и при пользовательском вводе): все space-like символы (tab, newline
и пр.) → обычный пробел; повторные пробелы схлопываются в один; края обрезаются. Поэтому текст замечания — одна
логическая строка; «несколько строк» в UI = перенос по словам, не литеральные `\n`.

### Лист «Иерархия»

Вложенный вид, **порядок строк = структура и сортировка**:

| Уровень 1 | Уровень 2 | Фиксированный |
|-----------|-----------|---------------|
| Документация |        | TRUE |
|            | Здание    | TRUE |
|            | Другое    |      |
| Общее      |           | TRUE |
|            | Другое    |      |
| Помещение  |           |      |
|            | Помещение | TRUE |
|            | Щит / панель |   |

Парсинг: непустой «Уровень 1» открывает узел уровня 1; последующие строки с непустым «Уровень 2» — его дети до
следующего «Уровень 1». «Фиксированный» = `TRUE` / пусто (пусто = изменяемый).

### Лист «Замечания»

Колонки: **`Категория`, `Текст`, `Область`** (именно в таком порядке). «Область» — это привязка (§3.2).
«Категория» заполнена сверху вниз (группировка, как «Уровень 1» в листе «Иерархия»): пустая ячейка = та же
категория, что строкой выше. Порядок строк внутри категории = заданный порядок замечаний.

| Категория | Текст | Область |
|-----------|-------|---------|
| Покраска | Покрасить жёлтую дверь в синий цвет | Помещение |
|          | Дверь скрипит при открывании | Помещение |
| Таблички | Табличка «Не влезай» висит, а лестницы нет | Помещение |

(Строки в духе тестовой фикстуры `test/fixtures/catalog.xlsx`. «Область: Помещение» → фиксированный лист
«Помещение» и все «Щит / панель».)

## 5. Обновление каталога

- Команда — пункт **«Обновить каталог»** в меню (**☰**) экрана «Список аудитов». Ход чтения показывает
  спиннер в диалоге обновления.
- Тянет оба CSV, при успехе **полностью заменяет** локальный кэш иерархии и каталога. На аудиты не влияет;
  про пользовательский список — ниже.
- **Семантика бинарная:** каталог применяется целиком только если ошибок нет; при любой ошибке **не применяется** —
  остаётся прежний кэш.
- **Ошибок ровно две** (остальное не репортим):
  1. **Иерархия:** на каком-то уровне не ровно один изменяемый слот (0 или >1).
  2. **Замечание:** привязка ссылается на несуществующее имя узла иерархии.
- **Диалог обновления:** спиннер → результат. Успех: «✓ Каталог обновлён». Ошибки: «Каталог не обновлён» +
  список ошибок. Кнопки «Закрыть» / «Повторить». Офлайн/сеть недоступна → та же логика (ошибка, старый кэш цел).
- **Слияние с пользовательским списком (только при успешной загрузке):** если текст пользовательского замечания
  совпадает (без регистра, обрезка пробелов) с текстом какого-то предопределённого — пользовательское замечание
  **удаляется** из списка; его настройки (категория, привязка) теряются. Выбранные в аудитах замечания не
  затрагиваются (хранятся снимком по тексту).

## 6. Интерфейс

Визуальный эталон — `layout-mockup.html` (визуальный язык), но **раскладка низа/добавления в нём устарела**:
он рисует футер «[Поиск] Добавить», тогда как в V3 внизу только круглая кнопка-лупа, а «Добавить» переехал
в заголовки секций (см. §6.1 и мокапы ниже — они актуальнее макета). Визуальный язык: **строгий минимализм** —
плоские списки на тонких линиях, без карточек и теней. Светлая/тёмная тема. Комфортные тач-таргеты (~46px).

### 6.1. Общий каркас экрана

- **Шапка** (липкая сверху): кнопка «назад» слева (опционально), **заголовок по центру** (это **название**
  текущего элемента — аудита/здания/узла/листа; у фиксированных узлов — имя слота из шаблона). У **правого
  края** шапки — иконка **✎** (только для редактируемых элементов; открывает модалку правки названия, §6.9).
- **Контент** (скроллится): список (плюс фиксированные узлы, где есть). Отдельного поля «Название» в контенте
  больше нет — название правится через ✎ в шапке. Нижний отступ резервирует место под плавающие кнопки.
- **Низ**: **круглая кнопка поиска** (иконка-лупа) внизу-справа поверх контента; выделенного футера нет.
  По ней снизу раскрывается **поле поиска** (с крестиком × для очистки) + «Отмена» (закрыть и сбросить фильтр).
  Слева, зеркально лупе, — опциональная **круглая кнопка вторичного действия**: **⤓** экспорт (экраны аудита
  и «Мои замечания») либо **☰** меню (список аудитов, §6.3).
- **Добавление** — плавающая кнопка **«Добавить»** внизу по центру (поверх контента, рядом с лупой).
  По ней в списке появляется **inline-строка с полем ввода** (фокус сразу): Enter/расфокус с непустым именем
  создаёт элемент и оставляет в списке (внутрь не переходим), пустой — исчезает бесследно. По одному за раз.
  Исключение — экраны замечаний: там «Добавить» открывает модалку (§6.8), а не inline-строку.

### 6.2. Строки списка (набор вариантов)

| Вариант | Состав | Где |
|---|---|---|
| строка-переход | заголовок (+подзаголовок) + счётчик справа | аудиты, здания, узлы |
| строка-drag | ⠿ хендл + название + счётчик | изменяемые экземпляры |
| строка-фикс | название + счётчик | фиксированные узлы |
| заголовок секции | подпись слева + «Добавить» справа | над добавляемым списком |
| inline-строка | только поле ввода имени (по «Добавить») | верх/низ списка |
| строка-категория | ▸/▾ + название + `[выбрано/всего]` | экран замечаний, «Мои замечания» |
| строка-замечание | ☐ + текст (многострочный по словам) | экран замечаний |

**Правка названия** — иконка **✎** справа от заголовка в шапке (только у редактируемых элементов). Открывает
модалку с одним полем и кнопками «Удалить»/«Сохранить» (§6.9). Отдельного поля «Название» в контенте нет.

**Удаление** — кнопка «Удалить» в той же модалке правки названия, с подтверждением (§6.9).

### 6.3. Экран «Список аудитов»

```
+------------------------------+
|          АУДИТОР             |
+==============================+
| Аудиты                       |
| Театр Оперы и Балета      27 |
| 2 дня назад                  |
|------------------------------|
| Автозаправка               7 |
| 5 дней назад                 |
|------------------------------|
| Цирк                     315 |
| 17 июля 2026                 |
|      (☰)   [ Добавить ]  (⌕) |
+------------------------------+
```
- Внизу слева — **☰**: раскрывает вверх меню с пунктами **«Мои замечания»** (§6.7) и **«Обновить каталог»** (§5).
- Список аудитов сортируется по `time`. Строка: название, счётчик замечаний по аудиту, дата.
- «Добавить» (плавающая кнопка внизу по центру); новый аудит встаёт в начало списка (самый свежий).

### 6.4. Экран аудита (список зданий)

```
+------------------------------+
| ‹  Театр Оперы и Балета ✎    |
+==============================+
| Здания                       |
| ⠿ Гараж                   18 |
| ⠿ Основное здание          9 |
|      (⤓)   [ Добавить ]  (⌕) |
+------------------------------+
```
- Заголовок — название аудита; **✎** открывает модалку правки (§6.9), там же удаление. Слева внизу — **⤓**
  экспорт аудита (V2). Список зданий — ручная сортировка (drag). «Добавить» открывает inline-строку;
  новое здание встаёт в конец списка.

### 6.5. Экран здания (список уровня 1)

```
+------------------------------+
| ‹        Гараж  ✎            |
+==============================+
| Документация               8 |
| Общее                      5 |
| Помещение                    |
| ⠿ Основное строение        3 |
| ⠿ Подвал                   2 |
|            [ Добавить ]  (⌕) |
+------------------------------+
```
- Заголовок — название здания; **✎** — правка/удаление (§6.9). Фиксированные слоты уровня 1 сверху, ниже —
  единственная изменяемая группа (подпись-заголовок + drag-список; «Добавить» — плавающая кнопка внизу).

### 6.6. Экран узла уровня 1 / уровня 2

Экран уровня 1 (напр. «Помещение») устроен как §6.5, но списком уровня 2. Правка названия (**✎** в шапке) —
**только для нефиксированных** узлов; у фиксированных заголовок — имя слота из шаблона, без ✎.

Экран уровня 2 — **список замечаний** (заголовок — имя листа; **✎** для нефиксированных):

```
+------------------------------+
| ‹      Щит ЧЗНХ №12  ✎       |
+==============================+
| Замечания                    |
| ▸ Основное              0/17 |
| ▾ Электрика              1/2 |
|   ☑ Нет заземления           |
|   ☐ Нет выключателя по       |
|     ГОСТ 1234-56-78          |
| ▸ Прочее                0/21 |
|            [ Добавить ]  (⌕) |
+------------------------------+
```
- Двухуровневый список: категории (сворачиваемые, сортировка по имени, «Прочее» внизу) → замечания (☐/☑).
- Показываются только замечания, чья привязка подходит листу (§3.2): предопределённые (в заданном порядке),
  затем пользовательские (по алфавиту). Пользовательские визуально не выделяются.
- «Добавить» (в заголовке секции «Замечания») открывает модалку создания замечания (§6.8), не inline-строку.

### 6.7. Экран «Мои замечания» (CRUD пользовательского списка)

Стандартный каркас; список пользовательских замечаний с группировкой по категориям и поиском. Секция
«Замечания» с «Добавить» (открывает модалку создания, §6.8). **Без чекбоксов.** Клик по замечанию → модалка правки (§6.8). Правки отражаются во всех аудитах по совпадению
текста; удаление — из модалки. Вход — через меню **☰** → «Мои замечания» с главного экрана. Экспорт списка
(V2) — круглая кнопка **⤓** внизу слева.

### 6.8. Модалка замечания (создание/правка)

```
+------------------------------+
| Отмена       Замечание       |
+------------------------------+
| ТЕКСТ                        |
| [ многострочное поле        ]|
| КАТЕГОРИЯ                     |
| [ ввод/выбор с подсказками  ]|
| ПРИМЕНИМО К                   |
| ☑ Документация               |
| ☑ Другое                     |
| ☑ Здание                     |
| ☑ Общее                      |
| ☑ Помещение                  |
| ☑ Щит / панель               |
+------------------------------+
| [Удалить]         Сохранить  |
+------------------------------+
```
- **Текст** — многострочное поле (ввод; на выходе нормализуется, §4).
- **Категория** — поле с подсказками (автодополнение из существующих категорий + ввод новой).
- **Применимо к** — чекбоксы = все имена узлов иерархии (уровни 1 и 2), **уникальные, по алфавиту**. По умолчанию
  **все отмечены**; последний выбор **запоминается в рамках сессии** (сброс после перезагрузки).
  **Последняя отмеченная галочка не снимается**: состояния «нигде» не существует (пустая привязка означает
  «применимо везде», и снятие всех галочек молча инвертировало бы смысл).
- **«Удалить»** — только в режиме правки.
- **Создание из листа** (кнопка «Добавить» на экране замечаний): новое замечание попадает в глобальный список
  **и сразу отмечается** в текущем листе.

### 6.9. Диалоги

- **Модалка правки названия** (по ✎) — тот же каркас, что у модалки замечания (§6.8): в шапке «Отмена»,
  внизу «Удалить»/«Сохранить». Одно поле «Название» (обязательное — «Сохранить» недоступно при пустом).
  «Удалить» — с подтверждением (диалог ниже). Для аудита/здания/нефиксированного узла/листа.
- **Меню (☰)** — на главном экране: круглая кнопка внизу слева (зеркально лупе); раскрывает у себя
  поповер (для нижней кнопки — вверх) с пунктами «Мои замечания» и «Обновить каталог». Закрывается по
  выбору пункта, клику мимо и системной «Назад».
- **Подтверждение удаления** — центральный модальный диалог «Удалить?» с пояснением (удаляются вложенные
  замечания, действие необратимо) и красной кнопкой «Удалить». Для удаления аудита/здания/узла.
- **Диалог обновления каталога** — см. §5.

## 7. Поведение

- **Поиск** — фильтрация текущего списка по подстроке в реальном времени, без учёта регистра; область — только
  текущий экран. Совпавшая часть **подсвечивается** (обёртка в `<span>`). На экране замечаний категории с
  совпадениями остаются раскрытыми.
- **Удаление** — модальный диалог подтверждения (§6.9). Отметка/снятие замечания — без подтверждения.
- **Сохранение** — авто-сохранение в IndexedDB при любом изменении; кнопки «Сохранить» нет. `time` аудита
  обновляется при каждом изменении внутри него. **Сбой записи** (квота, приватный режим) — не молча:
  показывается закрываемый баннер «Не удалось сохранить данные».
- **Обязательные имена** — пустые имена недопустимы нигде (аудит, здание, узел). Имя задаётся сразу при
  создании в **inline-строке** (§6.1): пустой ввод в модель не попадает вовсе, поэтому «нового пустого»
  элемента не бывает. Переименование — только через модалку правки (§6.9), где «Сохранить» недоступно при
  пустом поле, так что имя нельзя стереть. Отдельного guard'а на навигацию больше нет — пустого имени
  просто не возникает.
- **Безопасность рендеринга** — любые строки пользователя/CSV выводить через `textContent` / DOM-узлы, не через
  `innerHTML` с сырой строкой (символ `<` и пр.). Подсветку поиска строить из `createTextNode` + `<span>`.

## 8. Проверка

- **Ядро отдельно от DOM** (`src/core/*.ts`) → тестируется в Bun без браузера.
- **`bun test` на фикстурах.** Ключевые тест-кейсы: правило привязки; обратимость разрешения имён; слияние
  снимка с иерархией; агрегация счётчиков; сирота-замечание → «Прочее»; бинарная валидация каталога (две ошибки);
  слияние с пользовательским списком; нормализация строк.
- **Фикстуры** в репозитории — тесты и локальная разработка не зависят от сети. *(V2: CSV-фикстуры
  заменены xlsx-файлами `test/fixtures/catalog*.xlsx`; «Обновить каталог» тестируется на собранных
  writer'ом книгах, см. `VERSION_2.md`.)*
- **Ручной прогон** — `bun start` на десктопе и телефоне (localhost).
- **E2E (Playwright)** на потоки: создать аудит → добавить узлы → отметить замечания → перезагрузка (персист) →
  обновление каталога. *(Офлайн-сценарий через Service Worker — в Версии 3.)*

**Порядок сборки версии:** (1) ядро + юнит-тесты на фикстурах; (2) загрузчик каталога (CSV→кэш) + mock-fetch;
(3) каркас вёрстки + один экран на реальных данных; (4) остальные экраны, drag, модалки, поиск, удаление.

## 9. Обоснования решений (почему так)

- **Платформа — веб/offline.** Работа на объекте с телефона, портретные экраны; сеть нестабильна, поэтому
  данные локально (IndexedDB), а не на бэкенде.
- **Ровно один изменяемый слот на уровень** (не «не более»). Снимок аудита хранит путь по именам и разрешается
  против текущей иерархии: имя, не совпавшее с фиксированным слотом, должно «падать» в изменяемый. Нет
  изменяемого или их больше одного — падать некуда/неоднозначно. Отсюда же бинарная валидация отвергает такую
  иерархию целиком.
- **Снимок вместо ссылок (нет стабильных ID).** Аудит самодостаточен: правки/удаление в каталоге его не ломают.
  Связь — по совпадению текста. Осознанно делает поведение при правках иерархии обратимым (убрали узел →
  замечания переехали; вернули → встали на место). ID усложнили бы модель без пользы.
- **Явное хранение всех узлов аудита (включая фиксированные) + вложенная структура.** Нужны ручной порядок
  экземпляров (drag) и сохранение пустых узлов — плоский список замечаний это не выражает.
- **Обновление каталога — бинарное, ровно две ошибки.** Частично применённый каталог сбивает с толку; проще
  «всё или ничего». Репортим только структурную ошибку иерархии и ссылку замечания на несуществующий узел.
- **Пользовательские замечания — глобальный список + отдельный экран «Мои замечания».** Редактирование вынесено
  из списка выбора. Поэтому же **убрали звёздочку**-метку в списке выбора: оттуда их не редактируют, метить нечего.
- **Нормализация строк и безопасный рендер.** CSV правит человек: space-like → пробел, схлопывание двойных,
  обрезка краёв — иначе сравнение по тексту непредсказуемо. Ту же нормализацию — к пользовательскому вводу.
  Рендер строк — только через `textContent`/DOM (символ `<` и пр.), без сырого `innerHTML`.

**Отклонённые/пересмотренные варианты:** плоский `items[]` в аудите → вложенное дерево; «пропускать плохие
строки каталога» (не-фатально) → бинарная семантика; звёздочка-метка пользовательских в списке выбора → убрана.
