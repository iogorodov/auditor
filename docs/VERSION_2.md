# Версия 2 — экспорт и каталог через `.xlsx`

Добавляет выгрузку данных и переводит обновление каталога на файлы. Опирается на модель данных Версии 1.

- **Аудит → `.xlsx`** — итоговый документ с замечаниями.
- **Пользовательские замечания → `.xlsx`** — выгрузка глобального списка.
- **Обновление каталога — из `.xlsx`-файла** (выбор файла на устройстве) вместо загрузки CSV из
  Google-таблицы (V1, §5). Правила самого обновления не меняются: бинарная валидация, «всё или ничего»,
  слияние пользовательского списка.

Генерация и чтение — на устройстве, в браузере (offline), без бэкенда.

## Обоснования смены дизайна (вместо docx и Google-таблицы)

- **Один формат на вход и выход.** Каталог приходит как `.xlsx`, выгрузки уходят как `.xlsx` —
  один и тот же собственный код, круговой сценарий «выгрузил список → дополнил каталог → загрузил обратно».
- **Полный офлайн без CORS.** Файл выбирается локально; сетевой путь (и его ошибки) исчезает.
- **Без тяжёлых библиотек.** Готовые библиотеки, умеющие и читать и писать xlsx, избыточны для наших
  задач. Вместо них — собственный код (см. ниже), единственная зависимость — fflate (~8 КБ, zip/unzip).

## Основа: собственный xlsx-код (`src/xlsx`)

Перенесён из другого проекта автора, работает, покрыт тестами (`test/xlsx/*`). Слои:

- `descriptor.ts` — типобезопасный билдер схем объектов (типы свойств + Meta; не даёт недоописать тип).
- `serialize.ts` — обходчики `write`/`read` по схеме через интерфейсы `Writer`/`Reader`;
  `json.ts` (Writer+Reader), `xml.ts` (пока только `XmlWriter`).
- `xlsx-types.ts`, `xlsx-style-types.ts` — типизированные модели частей OOXML (content types, rels,
  workbook, worksheet, styles) как схемы поверх сериализатора.
- `xlsx-build.ts`, `styles-collector.ts`, `hyperlink-collector.ts`, `xlsx.ts` —
  `buildXlsxFile(sheets)`: сборка книги из простого входа `Worksheet {name, columns, headers, data}`
  и упаковка fflate'ом.

Код лежит плоско в одном каталоге, стиль исходного проекта сохранён. Браузерных API не использует —
тестируется в `bun test`.

## Чтение `.xlsx` (дописать)

Решение: **строгие типизированные схемы, как и для записи.** Файлы от Excel / Google Sheets отличаются
от нашего вывода — это кодируется расширением типов, а интерпретация пишется поверх «обычных» объектов:

- `XmlReader` (реализация `Reader<XmlMeta>` по образцу `JSONReader`): поиск по локальному имени
  (терпимость к префиксам неймспейсов), `null` для отсутствующих `*Null`-полей.
- Под ним — собственный мини-парсер XML → дерево узлов (элементы, атрибуты, entities; подсет,
  достаточный для машинного XML из xlsx). Браузерный DOMParser не используем: ядро без браузера,
  один код-путь в тестах и в проде.
- Схемы-надмножества для чужих файлов: `sharedStrings.xml` (`t="s"` + rich-text runs `<r><t>`),
  `t="inlineStr"` (`<is><t>`), `t="b"` (галочка «Фиксированный» → 0/1), числа без `t`;
  путь к листу — только через workbook.xml + rels (Excel пишет `xl/worksheets/sheet1.xml`,
  наш writer — `xl/sheet1.xml`); разреженные строки — колонка из атрибута `r` ячейки.
- Выход ридера — листы как `string[][]`; дальше — существующая логика каталога V1
  (`core/sheets.ts`: `parseHierarchyRows`/`parseCatalogRows` со входом «строки таблицы»; CSV-путь и
  papaparse удалены, валидация и слияние не менялись).
- Фикстуры: реальные файлы, сохранённые из Excel и Google Sheets (`test/fixtures/catalog.xlsx` — Excel, `catalog-sheets.xlsx` — Google Sheets), плюс
  round-trip «записали своим writer'ом → прочитали».

## Экспорт аудита в `.xlsx`

- Точка входа: иконка ⤓ в шапке экрана аудита. Файл — `<название аудита>.xlsx`, лист назван по аудиту
  (недопустимые символы вычищаются, длина ≤ 31).
- **Раскладка (согласована с заказчиком).** Один лист, 4 колонки, без строки заголовков.
  Каждое здание открывается строкой с названием в первой ячейке; далее — строки замечаний:
  `№ (сквозная нумерация на весь документ) | Уровень 1 | Уровень 2 | Замечание`.

  ```
  | Гараж |              |            |                      |
  |     1 | Документация | Здание     | Слишком красный цвет |
  |     2 | Общее        | Другое     | Нет крыши            |
  | Сарай |              |            |                      |
  |     3 | Помещение 1  | Щит ЧЗНХ 1 | Нет заземления       |
  ```
- Пустые узлы и здания без замечаний в документ не попадают. Категории не выгружаются.
- Порядок зданий/узлов — как в приложении (разрешение через шаблон); порядок замечаний в листе —
  порядок каталога (не порядок отметки), не-каталожные — после, по алфавиту.

## Экспорт пользовательских замечаний в `.xlsx`

- Точка входа: иконка ⤓ в шапке экрана «Мои замечания». Файл — `Мои замечания.xlsx`, лист «Замечания».
- Колонки зеркалят лист «Замечания» каталога (со строкой заголовков): `Категория | Текст | Область`
  (имена через `;`) — список можно дополнить в каталог и загрузить обратно.
- Категория пишется в каждой строке явно (пустая ячейка при импорте означала бы «категория строкой
  выше»); пустая категория выгружается как «Прочее». Порядок — как на экране: категории по алфавиту
  («Прочее» внизу), тексты по алфавиту.

## Проверка

- Юнит-тесты на формирование структуры документа из модели и на чтение (фикстуры из Excel /
  Google Sheets, round-trip с writer'ом) — всё в `bun test`, без браузера.
- Ручная проверка: открытие выгрузок в Excel / Google Sheets / Numbers; обновление каталога из
  файла, сохранённого обеими программами.
